1. INTRODUCTION                                            *vim-notebox-intro*

vim-notebox is a modified zettelkasten implementation for local note taking and
knowledge-base work.  Notes are plain Markdown files with a YAML header, all
stored flat inside a "note box" directory.  In addition to manual notes, a set
of Python scripts can fetch external data (Ministry of Foreign Affairs pages,
World Bank indicators, CIA World Leaders, Trade Map trade figures, Trade
Ministry country-profile PDFs, country maps) and turn them into notes that are
linked into per-country "dashboard" pages.

The plugin is written in |vim9script|.

Main features:
  - Flat note storage; every note is `<epoch-id>.md`.
  - YAML front matter with an `n_type` classification and per-note bibfile.
  - Automatic back-references and an orphan-notes report.
  - Keyword search across the box, with quickfix integration.
  - "Note boxes": several note directories you can switch between.
  - One-line commands/mappings to fetch a whole country's information notes.
  - Freshness gate: recent reports are not re-downloaded; older ones prompt.
  - `--delete` (and vim delete commands) to remove generated note sets.
  - Pandoc export to PDF/DOCX/beamer.
  - Per-country HTML export of the automatic information notes (OBN).

2. REQUIREMENTS AND INSTALLATION                            *vim-notebox-install*

Requirements ~
  - Vim 9 with |vim9script|.
  - The `bibtexcite.vim` plugin (used for per-note bibliography files).
  - Python 3 and the script dependencies.

Install ~
  1. Place the plugin so `plugin/` and `ftplugin/` are in your 'runtimepath'
     (for example `~/.vim/plugged/vim-notebox`).

  2. Install the Python dependencies into the bundled virtualenv:
>
     cd <plugin>/plugin/scripts
     python3 -m venv venv
     venv/bin/python3 -m pip install -r requirements.txt
<
     The Vim wrappers run the scripts with `plugin/scripts/venv/bin/python3`
     by default (change with the `g:*_python` options, see
     |vim-notebox-config|).  Direct CLI runs use the shebang instead; see
     step 5 below.

  3. Set your note box and, optionally, your name:
>
     let g:notes_directory = '~/notes'
     let g:notes_author    = 'Your Name'
<

  4. Generate the help tags so `:help vim-notebox` works:
>
     :helptags <plugin>/doc
<
     If the plugin is installed as a normal runtimepath package you can run
     `:helptags ALL` instead.

  5. The Python scripts are directly executable:
>
     cd <plugin>/plugin/scripts
     ./getDbn.py NPL --box ~/notes
     ./getCountry.py Nepal --box ~/notes
<
     Their shebang points at the bundled virtualenv, so no activation is
     needed.  If the plugin directory moves, update the shebang (or run the
     scripts with `venv/bin/python3`).  If an archive lost the executable bit:
>
     chmod +x <plugin>/plugin/scripts/get*.py
<

  6. (PDF/DOCX export only) Install `pandoc`, `pandoc-crossref`,
     `pandoc-plot`, and view the helpers `links-to-pdf.lua` and
     `table-border.lua` under `$HOME/.bin`, plus `zathura` and
     `onlyOffice.AppImage`.

3. QUICK START                                          *vim-notebox-quickstart*

A short end-to-end example.  Start by choosing a note box (see
|g:notes_directory| and |g:boxes|):
>
     :Choosebox
<
Then create a manual note:
>
     :Newnote Nepal delegation meeting
<
Fetch all auto-generated pages for one country (a live log window is opened and
the country dashboard is shown when finished):
>
     :Countryfetch Nepal
<
If a trade or profile report already exists and is older than the threshold, a
confirmation dialog appears, e.g.
>
     Yeni Zelanda Dış Ticaret Rakamları 2 gün önce güncellendi.
     Yeni rapor oluşturulsun mu? (E/H)
     [Yeni Zelanda Foreign Trade Figures were updated 2 days ago.
      Generate a new report? (Yes/No)]
<
Choose "Evet" (Yes) to regenerate, "Hayır" (No) to keep the old report.  Fresh
reports are skipped silently and reported as "yenilenmedi" (not refreshed).

Afterwards you can open the country dashboard, write back-references, and export
to PDF:
>
     :Whichbox
     :Writeback
     :Viewpdf
<
Auto-fetched notes are grouped per country: the country dashboard
(`hub {iso3}`) links to a per-country "Otomatik Bilgi Notları" page, which in
turn links the per-type index pages.  See |vim-notebox-note-types|.

Environment variables ~
  The scripts also read these (set by the wrappers): `NOTES_DIR`,
  `NOTES_BIB_DIR`, `NOTES_AUTOHUB`, `NOTES_MAP_HEIGHT`,
  `NOTES_REPORT_MAX_AGE_DAYS`, `NOTES_WB_REPORT_MAX_AGE_DAYS`,
  `NOTES_LEADERS_REPORT_MAX_AGE_DAYS`,
  `NOTES_TBUP_REPORT_MAX_AGE_DAYS`, `NOTES_TUBITAK_REPORT_MAX_AGE_DAYS`,
  `NOTES_KOSGEB_REPORT_MAX_AGE_DAYS`, `NOTES_TUYSGM_REPORT_MAX_AGE_DAYS`,
  `NOTES_OTHERBN_REPORT_MAX_AGE_DAYS`, `TBUP_PDF_DIR`, `GMAP_NOTES_DIR`,
  `GMAP_MAPS_DIR`.

  getData.py additionally reads `NOTES_WB_HTTP_RETRIES` (default 4, number
  of download attempts per request) and `NOTES_WB_CURL` (curl binary,
  default `curl` from `$PATH`).

  `NOTES_HTTP_RETRIES` (default 4) is the attempt count for the scripts
  that use Python `requests` (getLeaders.py, getDbn.py, getMap.py,
  getStmd.py, getTmd.py, getTbupPdf.py).  Connection resets, timeouts and
  429/5xx answers are retried with a short pause; 404 and other 4xx answers
  are reported at once.  Set it to 1 to disable retrying.
                                                       *NOTES_HTTP_RETRIES*

  getTuysgmNotes.py also uses `SOFFICE_BIN` (default `soffice`) for the
  LibreOffice `.doc` -> HTML conversion.

5. CORE NOTE MANAGEMENT                                       *vim-notebox-notes*

Commands ~
                                                                   *:Newnote*
:Newnote {title}       Create a new note `<epoch-id>.md` from the skeleton,
                       set id/date/citation-style/bibfile and title.

                                                                  *:Writeback*
:Writeback             Rebuild the current note's `#BackReferences:` section
                       from other notes that reference it.

                                                                *:Getnoteid*
:Getnoteid {file}      Read the numeric id stored in a note's YAML header.
                       The command itself prints nothing.

                                                              *:Openlastnote*
:Openlastnote          Open the most recently modified note.

                                                                   *:Openbox*
:Openbox               Edit the note box as a directory (netrw).

                                                                 *:Choosebox*
:Choosebox             Pick a box from |g:boxes| and `cd` into it.

                                                                *:Notesearch*
:Notesearch {kw;kw}    Search the box for keywords (semicolon-separated, all
                       must match) and list results in the quickfix list.

                                                            *:NoteSearchInbox*
:NoteSearchInbox {kw}  Like |:Notesearch| but asks for a box first.

                                                                 *:Whichbox*
:Whichbox              Echo the active note box.

                                                                  *:Orphans*
:Orphans               Open an unsaved `OrphanNotes.md` buffer listing notes
                       that nothing references.  Save it with `:w` to keep it.

                                                                *:Lastnotes*
:Lastnotes {n}         List the N most recent notes in the quickfix list.

                                                               *:Modifydate*
:Modifydate            Update the `modify:` field of the current note to today.

Mappings (default <Leader>) ~
  <Leader>nn    :Newnote
  <Leader>yn    Yank a Markdown link to the current note
  <Leader>ob    :Openbox
  <Leader>ln    :Openlastnote
  <Leader>sb    :Choosebox
  <Leader>s     Search the word under the cursor
  <Leader>ns    :Notesearch
  <Leader>wb    :Whichbox
  <Leader>bl    :Writeback
  <Leader>nsb   :NoteSearchInbox
  <Leader>md    :Modifydate
  <Leader>cbf   Create a bibfile for the current note and write its path
  <Leader>obf   Open the current note's bibfile
  <Leader>lbf   Load the current note's bibfile into bibtexcite

Backlinks and orphans: the `#BackReferences:` section at the end of a note is
preserved across rewrites (only the note body above it is regenerated).

6. DATA FETCHERS                                               *vim-notebox-fetch*

Each fetcher has a `:Xxxfetch` command (generate) and a `:Xxxdelete` command
(remove the generated notes for a country); see |vim-notebox-delete|.

Command-line messages ~
  Each command identifies the Python script and what it does, both in the
  input prompt and while it runs:
>
     getDbn.py — Dışişleri Bakanlığı ülke notları — Ülke (iso3/ad):
     getTbupNotes.py — Ticaret Bakanlığı ülke profili — Nepal çalışıyor...
<
  During |:Countryfetch| every generator updates the command line when it
  starts and finishes (for example `getDbn.py — ...` then `getDbn.py — OK`);
  the full output remains in the `[Countryfetch]` window.  See
  |g:notebox_verbose| to silence progress messages and |g:notebox_fetch_desc|
  to change the descriptions.

:Countryfetch {country} [year]                                *:Countryfetch*
  <Leader>cf
  Run getCountry.py: generate every auto page for a country (MFA web notes,
  World Bank indicators, CIA World Leaders, single + bilateral trade, Trade

  the country's `perm cvb` profiles, map, Dokümanlar page), link them into
  the country dashboard and open it.
  The Trade Map year is optional.  When omitted, the trade scripts use the
  newest year that has data for both imports and exports; an explicit year
  (e.g. `:Countryfetch Nepal 2024`) still overrides it.
  Runs async; shows a live log.  Accepts ISO3 or a Turkish name (e.g. `Nepal`).
  The World Bank step writes one diagnostic line per indicator into the
  same log; see |:Wbfetch|.  The Vim command has no force option; run the
  script directly with `--force` to bypass the freshness gates.

:Wbfetch {country}                                               *:Wbfetch*
  <Leader>wbr
  Run getData.py: creates two World Bank notes ("Gösterge Raporları" —
  Indicator Reports), both `n_type: obn indicatorReport`:
>
     <Ülke> İlk Bakış                  general country table
     <Ülke> Temel Ekonomik Göstergeler comparison table from the şablon note
<
  Both are listed in the per-country indicator index.  The second note uses
  the row order, Türkiye values, caption and footnote of the note
  "Türkiye Son Ekonomik Gösterge Rakamları" (`n_type: şablon`).  Country
  values are rounded to two decimal places uniformly.  Year placeholders in
  the şablon row labels (`{year1}`, `{year2}`, ...) are replaced with the
  endpoint year for that indicator.  A fetched value is always written,
  even when its year differs from the placeholder; the şablon year is only a
  label.  If no year is available, the placeholder is removed.

  The run is asynchronous by default (|g:wb_async|).  Every indicator gets
  a diagnostic line, streamed live into the `[Wbfetch]` scratch buffer and
  echoed on the command line:
>
     --- getData.py: [ 1/13] Nüfus (SP.POP.TOTL) — önbellek (0.2 gün):
         85.88M (2025) | WB 2026-11-11
     --- getData.py: [ 2/13] GSYH ($) (NY.GDP.MKTP.CD) — endpoint: 1.60T
         (2025) | HTTP 200 | WB 2026-11-11 | 0.07 sn | 2 deneme
     --- getData.py: ÖZET (artımlı): 13 gösterge — 12 önbellek, 0 endpoint,
         0 veri yok, 0 hata, 1 atlandı; modify 18/11/26; veri data/tur/wbdata
<
  The source is shown as `endpoint` (downloaded now), `önbellek` (read from
  the cache file, with its age) or `eski önbellek` (the download failed and
  an expired file was used instead); missing values, download errors and
  template rows without a matching indicator code are reported too.  Lines
  beginning with `...` are extra detail (for example "istek gönderildi")
  and appear only in the buffer; `---` lines are also echoed on the command
  line.  The buffer closes on success unless |g:wb_keep_log| is 1; on
  failure it stays open and is shown even if it was hidden.

  Downloaded JSON is cached inside the note box, one file per object:
>
     data/<iso3>/wbdata/general.json             country fact sheet
     data/<iso3>/wbdata/indicators/<CODE>.json   one indicator
     data/<iso3>/wbdata/manifest.json            resolved values and years
<
  For `Yeni Zelanda` that is `data/nzl/wbdata/`; the folder is created when
  missing.  Every indicator is fetched on its own with `mrnev=1` (most
  recent non-empty value, a single row), because that parameter must not be
  combined with several indicators: the API then answers "The provided
  parameter value is not valid".

  Downloads use `curl` and are validated before they are kept: the answer
  is written to a `.part` file, parsed as JSON, and only then renamed over
  the cache file, so an interrupted download never overwrites good data.
  Connection resets are retried by the script (not by curl's own `--retry`,
  which fires its attempts back to back within a few milliseconds and lands
  them all in the same outage window): the attempts are separated by a
  short pause, which is what makes the second connection succeed.
  `NOTES_WB_HTTP_RETRIES` (default 4) sets the attempt count and appears in
  the diagnostic line as `N deneme`.  If three indicators in a row fail, the
  network is assumed down and the remaining rows are marked without being
  requested, so a dead connection ends in seconds instead of minutes.

  Freshness is decided by the **file date**, not by the note's `modify:`
  field: a cache file younger than `NOTES_WB_REPORT_MAX_AGE_DAYS` (default
  7) is used as is, an older one is downloaded again.  Each object is
  refreshed on its own, so one run can mix cached and fresh rows.  The
  country fact sheet is cached the same way.  A transport error is never
  recorded as `veri yok`: an expired cache file is preferred, the note's old
  value is kept if there is no file, and `modify:` is not advanced — so the
  next run retries instead of waiting out the age limit.  `--force` ignores
  the age, `--rebuild` reads only the cache and never touches the network.
  `:Wbcancel` stops a running fetch.

  See |vim-notebox-wb-incremental| for when values are reused and when all
  indicators are refreshed.

  To test the endpoint without writing notes or touching the cache, run the
  script directly with `--ping`; it prints the HTTP status and then every
  indicator with its year and value.

                                                        *vim-notebox-wb-incremental*
  The cache is the `wbdata/` folder, not the note.  Each downloaded object
  carries its own file date, and that date decides whether it is used or
  downloaded again:

  - file younger than |g:wb_report_max_age_days| (default 7): read from the
    file, no request
  - file at or after the limit, or missing: download that object again
  - `--force`: ignore every file date and download all of them
  - `--rebuild`: never download; build the notes from the cache only

  Because the decision is per file, a single run mixes cached and fresh
  rows: one expired indicator is refreshed while the other twelve are read
  from disk.  Nothing is shared between the country fact sheet and the
  indicators either — `general.json` expires on its own date.

  A failed download never becomes `veri yok`.  If an expired cache file
  exists it is used instead (shown as `eski önbellek` in the log and counted
  in the summary); without a file the value from the previous note is kept.
  In both cases `modify:` is not advanced and the summary says
  "modify korundu", so the next run retries those objects instead of
  waiting out the age limit.  Only a run without transport errors sets
  `modify:` to today.

  The year in a şablon row label is symbolic: successful fetches replace
  its `{yearN}` placeholder with the endpoint year, and no validation
  compares the two.  To refresh every row from a clean cache, use
  `--force`; to rebuild the notes after editing the şablon or the tables
  without any network access, use `--rebuild`.  `--clear-cache` deletes
  `data/<iso3>/wbdata/` and then continues normally.  `--delete` removes the
  indicator notes but keeps the cache; add `--delete-data` to remove the
  folder as well (`:Wbdelete` asks, default Hayır).  `Arge/GSYH % Oranı` has
  no row in the şablon note and is skipped with a diagnostic.

7. FRESHNESS GATE                                         *vim-notebox-freshness*

When a trade or country-profile report already exists, vim-notebox shows its
age and asks before regenerating:

  - Trade reports (|:Stmdfetch|, |:Tmdfetch|): threshold
    |g:country_report_max_age_days| (default 7).  |:Stmdfetch| checks both the
    table note and its "-Şekilli" companion, and a requested year that the
    note does not contain also counts as stale.
  - Country profiles (|:Tbupfetch|): threshold |g:tbup_report_max_age_days|
    (default 30).
  - CIA World Leaders notes (|:Leadersfetch|): threshold
    |g:leaders_report_max_age_days| (default 30).
  - TÜBİTAK, KOSGEB, TÜYSGM and other-institution notes: their own
    |g:tubitak_report_max_age_days| / |g:kosgeb_report_max_age_days| /
    |g:tuysgm_report_max_age_days| / |g:otherbn_report_max_age_days|
    (default 30 each).

The MFA web notes (|:Dbnfetch|) have no age gate; they are always re-fetched.

World Bank indicators (|:Wbfetch|) use an incremental, file-based refresh
instead of a confirmation dialog.  Every cached object under
`data/<iso3>/wbdata/` is considered separately, and its file date is
compared with |g:wb_report_max_age_days| (default 7).  Fresh files are read
from disk, expired ones are downloaded again, so a run can mix both.
`--force` ignores the dates and `--rebuild` never touches the network.
Because the age source is the cache file, updating the note with
|:Wbtable| does not reset the World Bank refresh window.  See
|vim-notebox-wb-incremental|.

Behaviour:
  - no report            -> generate.
  - age < threshold      -> keep the report, print
        "{title} N gün önce güncellendi (T günden yeni; yenilenmedi)"
        [updated N days ago (< T days); not refreshed].  No download.
  - age >= threshold     -> confirm dialog:
>
     {title} N gün önce güncellendi.
     Yeni rapor oluşturulsun mu? (E/H)
<
        "Evet" (Yes) regenerates; "Hayır" (No) opens the existing report.
  - Setting the matching `g:*_report_check` to 0 disables the gate for the
    Vim commands; those commands then run the script with `--force`.
  - Passing `--force` to a script always regenerates.  The same flag works on
    the umbrella script: `./getCountry.py Nepal 2025 --force` regenerates every
    gated report and re-downloads the map.
  - |:Countryfetch| itself does not pass `--force`; use the script directly
    when you need to override the gates for all sources at once.

The age is taken from the note's `modify:` field, or its `date:` field when
`modify:` is empty (the dialog says "oluşturuldu" = "created" in that case).

  by default.  To render them with the installed `mermaid-filter`:
>
  pandoc note.md -o note.pdf --filter mermaid-filter \
    --lua-filter ~/.bin/links-to-pdf.lua --citeproc
<
  `mermaid-filter` uses `mmdc` (mermaid-cli) and writes PNG files next to the
  note.  Set `MERMAID_FILTER_FORMAT=svg` to produce SVG instead.

  Country-profile charts are emitted as Pandoc Figure nodes (via
  `plugin/scripts/mermaid-figures.lua`), so `pandoc --lof` produces a List of
  Figures.  Tables use Pandoc's `: caption` syntax and `pandoc --lot`
  produces a List of Tables.  The generated YAML sets `lofTitle: "Şekiller"`
  and `lotTitle: "Tablolar"`.  The PDF, Beamer and DOCX commands put table
  and figure captions below with `--table-caption-position=below` and
  `--figure-caption-position=below`.

HTML export (country OBN pages) ~
:ObnHtmlExport {country}                                 *:ObnHtmlExport*
  <Leader>ohe
  Export the country's automatic information notes (OBN) as a standalone
  HTML site under `<box>/htmlExports/<Ülke>Notları/` (see
  |g:htmlexport_dir|).
  The country OBN hub (`hub obn {iso3}`) becomes `index.html`; every other
  country OBN note becomes `<id>.html`.  Only notes whose `n_type` contains
  `obn` and whose `country` matches the requested country are exported.  The
  `obn files` page, the global `obn-hub.md`, the country dashboard
  (`hub {iso3}`) and other countries' notes are excluded.  The
  `#BackReferences` block is removed and internal `.md` links to exported
  pages are rewritten to `.html`; links to excluded notes become plain text.
  The country map (`data/img/maps/{iso3}.png`) is copied as `map.png` and
  shown at the top of the home page.  A shared `style.css` is written next to
  the pages.  Local images referenced by the notes are copied into the export
  folder preserving their original relative paths (for example
  `data/img/portrait.png`), so images stay portable when the folder is moved.
  PDF/DOCX documents are not copied; their links are rebased relative to the
  export folder and therefore work only while the export stays inside the
  note box.  The home page is opened in the browser unless
  |g:htmlexport_open| is 0.  Accepts an ISO3 code or a Turkish country name
  (e.g. `Nepal` or `NPL`).  Mermaid blocks in the notes are rendered in the
  exported HTML: a local `mermaid.min.js` is copied when found (checked via
  `$OBN_MERMAID_JS`, `$MERMAID_JS`, `~/.bin`, `node_modules`, or the `mmdc`
  installation), otherwise the CDN build is referenced.

<Leader>dn             Delete the current note and any associated bibfiles.
                        There is no `:DeleteCurrentNote` command; the action
                        is available through this mapping (and `<Plug>Deletenote`).

12. PYTHON CLI REFERENCE                                         *vim-notebox-cli*

The wrapper commands run these scripts (see the wrapper for the exact
interpreter).  The scripts are also directly executable and accept two common
options of their own:

  --box DIR / --notes-dir DIR   note box to read and write.  Precedence:
                                `--box` > `$NOTES_DIR` > current directory.
  -h, --help                    print the script's usage and exit.

Running directly uses the interpreter named in the script's shebang (the
bundled virtualenv), not `g:*_python`; see |vim-notebox-install|.

Examples:
>
  cd <plugin>/plugin/scripts
  ./getDbn.py NPL --box ~/notes
  ./getData.py NPL --box ~/notes --check
  ./getCountry.py Nepal --box ~/notes --force
  ./getTbupNotes.py NZL --box ~/notes --check
  ./getObnFiles.py NZL --box ~/notes
  ./getMap.py NPL --box ~/notes --path
<

getCountry.py <country> [year] [--trade-year YYYY] [--skip-leaders]
              [--skip-stmd] [--skip-tmd] [--skip-tbup]
              [--skip-tubitak] [--skip-kosgeb] [--skip-tuysgm]
              [--skip-otherbn] [--skip-cv] [--skip-obnfiles]
              [--force] [--box DIR] [--delete] [--delete-data]
  Orchestrates all generators for a country.  The Trade Map year comes from
  the trailing `[year]` or `--trade-year`; when both are omitted, the trade
  scripts use the newest year with data for both imports and exports.
  `--skip-*` omits a step; `--force` bypasses every freshness gate and
  re-downloads the map; `--delete` removes the country's auto notes and OBN
  page, keeping `data/<iso3>/wbdata/`; add `--delete-data` to remove that
  JSON cache too (the rest of `data/<iso3>/` is never touched).

getDbn.py     <country> [--box DIR] [--delete]
getData.py    <country> [--box DIR] [--check] [--force] [--rebuild]
              [--clear-cache] [--delete] [--delete-data] [--ping]
  Creates two `obn indicatorReport` notes: `<Ülke> İlk Bakış` (general
  table) and `<Ülke> Temel Ekonomik Göstergeler` (comparison table built
  from the şablon note).  Both appear in the indicator index.  Downloaded
  JSON is cached under `data/<iso3>/wbdata/`.  `--check` reports the cache
  file count, staleness and the chosen mode without network access and
  without writing anything.  `--force` re-downloads everything,
  `--rebuild` builds from the cache only (no network), `--clear-cache`
  deletes the cache folder first, `--delete` removes the notes but keeps the
  cache (`--delete-data` removes that folder too), `--ping` tests the
  endpoint without writing.  Without these
  flags the age of each cache file selects cached or fresh data; see
  |vim-notebox-wb-incremental|.
getLeaders.py <country> [--box DIR] [--check] [--force] [--delete]
              [--link-only] [--slug SLUG]
  Creates `<Ülke> Liderler ve Kabine Üyeleri` (`obn leaders`) and links it
  directly on the country OBN page.  The global `Liderler ve Kabine Dizini`
  (`hub leaders`) lists every leaders note and is linked from `obn-hub.md`.
  `--check` reports the note age without network access; `--force`
  regenerates; `--link-only` refreshes the OBN/global links without network
  access; `--delete` removes the note, OBN section and global entry;
  `--slug` overrides the CIA page slug.

getObnFiles.py <country> [--box DIR] [--delete] [--dry-run] [--no-link]
  Create `<Ülke> Dokümanları` (`n_type: obn files`) from the documents used in
  OBN notes, `data/<iso3>` (except `eski/`, `img/`, `imgs/`, `maps/`,
  `sablonlar/`), country files in `data/documents`, and the TBUP PDF.  The page
  is linked on the country hub under `## Ülke Dokümanları`.  `--delete` removes
  only pages whose `author` is `getObnFiles`; `--dry-run` writes/deletes
  nothing; `--no-link` leaves the hub untouched.
getMap.py     <country> [--box DIR] [--path] [--dry-run] [--force]
getTbupPdf.py <country> [--dir DIR] [--box DIR] [--refresh]
exportObnHtml.py <country> [--box DIR] [--root DIR] [--out DIR] [--no-map]
                 [--no-clean] [--dry-run]
  Export the country's OBN pages as HTML.  The OBN hub becomes `index.html`,
  other pages `<id>.html`, the map is copied to `map.png` and a shared
  `style.css` is written.  Linked local images are copied into the export
  folder preserving their original relative paths; PDF/DOCX documents are not
  copied.  `--root` is the export root (default
  `htmlExports`); `--out` overrides the full output directory; `--no-map`
  skips the map; `--no-clean` keeps the existing folder; `--dry-run` only
  lists the plan.
wbTable.py <note.md | id> [--box DIR] [--template ID] [--stdout]
  Refresh the indicator table of an `obn indicatorReport` note from the
  current `n_type: şablon` note (default title: Türkiye Son Ekonomik Gösterge
  Rakamları).  In-place; no note/link changes.
generateCv.py <note.md | id | "Full Name"> [--box DIR] [--output FILE]
              [--id ID] [--image LINE] [--stdout] [--force] [--no-update]
generateCv.py <country> --all [--box DIR] [--image LINE] [--no-update]
  Create an `n_type: obn cv` grid-table CV from a `cvb`/`perm cvb` note.
  One CV is kept per source profile: an existing `obn cv` is updated, a legacy
  `cv` note is adopted, and no duplicate is created.  `--all <country>` scans
  all `perm cvb` profiles of that country.  The source note is not modified;
  the output has no `#BackReferences` block and no visible source link.
  Provenance is kept only in YAML as `cv_source: <source file name>`.  The CV
  is linked on the OBN page under `## CV Notları`.  Missing portraits produce
  a warning and a text cell.

Flag notes:
  --box DIR      active note box.  `--notes-dir` is an alias; `--box=DIR` is
                 accepted.  Without it, `$NOTES_DIR` (then cwd) is used.
  -h, --help     print the script's own usage/flag reference.
  --box with --dir: `--box` selects the note box (output, default source
                 roots); `--dir` overrides the source/download folder.
  --check        report the existing report's age only (no network, no
                 writes); prints REPORT_EXISTS / AGE_DAYS / AGE_SOURCE /
                 FRESH / AGE_TEXT lines.
  --link-only    (getLeaders) refresh the OBN and global directory links
                 without network access.
  --force        ignore the freshness gate and regenerate.
  --delete       remove the notes this script generated for the country and
                 update the indexes.
  --headings     (tbup, tubitak, kosgeb, tuysgm, otherbn) dry run: print the
                 outline and planned notes.
  --download-only (tbup) download the PDF and stop.
  --charts MODE  (tbup) chart output: table+mermaid (default), table,
                 mermaid, image, text.
  --no-disambiguate (tbup) keep raw heading titles.
  --skip-ekler   (tbup) do not generate EK-1…EK-6 table notes.
  --yes          (tbup, tubitak, kosgeb, tuysgm, otherbn) auto-confirm orphan
                 deletion / skip prompts.
  --no-prune     (tbup, tubitak, kosgeb, tuysgm, otherbn) never delete orphan
                 notes.
  --dir DIR      (tbup, tubitak, kosgeb, tuysgm, otherbn) alternate source
                 folder.
  --inst FOLDER  (otherbn) only process this institute folder.
  --no-dedup     (otherbn) disable document de-duplication.
  --dedup-threshold R  (otherbn) near-duplicate similarity threshold (0.90).
  --path         (map) print the target image path and exit.
  --root DIR     (exportObnHtml) export root relative to the box, or absolute
                 (default `htmlExports`).
  --out DIR      (exportObnHtml) exact output directory; overrides --root.
  --no-map       (exportObnHtml) do not copy/embed the country map.
  --no-clean     (exportObnHtml) keep the existing output folder.
  --dry-run      (exportObnHtml) list the pages that would be written.

13. TROUBLESHOOTING                                         *vim-notebox-trouble*

Fetchers fail with import errors ~
  The scripts use the bundled virtualenv.  Reinstall dependencies (see
  |vim-notebox-install|) or point the `g:*_python` option at your interpreter.

"No Data" / no report generated ~
  The source has no data for that country/pair, or the country does not report
  to Trade Map.  Nothing is written; the old note is kept.

A trade report shows "% Oran" as 0 ~
  The source's total for that direction is 0; the percentage is shown as 0
  instead of failing.

Duplicate notes appear ~
  Usually a code/notes mismatch of `n_type` values.  Regenerate with the
  current scripts; deletion commands can remove stale duplicates.

Back-links are stale ~
  Run |:Writeback| in the note, or |:Orphans| for the global list.

:help vim-notebox does not work ~
  Run `:helptags <plugin>/doc` (see |vim-notebox-install|).
